# Shared production and sales entry date

Manager has one Entry date at the top of the page, with Today and Yesterday shortcuts. It applies to Production and Sales. Switching dates clears unfinished production/sale forms only after confirmation. The selected date is preserved with the session draft. The sales list and confirmation show the selected day. Stock cards continue to show current stock, not reconstructed historic inventory.

Admin → Settings → Manager production & sales entry controls the previous-day allowance for both features. The existing setting key and API paths are retained for compatibility. Default 1 means today and yesterday; 0 means today only. Both create and correction endpoints enforce the current allowance in India time. Future dates and dates through the finalized import cutoff (12 September on this installation) remain blocked. Historical anonymous sales are unchanged; they must not be re-entered as new invoices. New sales still require a selected account or a name/phone and an explicit price.

Dated sales post invoices and money received with the sale to the selected date. Later payments belong in admin Customer Accounts with their actual payment date. FIFO customer allocation is recalculated; existing admin payment activity still blocks manager corrections. An existing invoice cannot be moved to another date. Request retry keys include the selected date in their comparison. `recorded_at` stores actual entry time for new invoices; old invoices retain an unknown recording date. Receipts distinguish sale date from entry time.

Sales consume currently unallocated batches eligible on the selected date: production must be at least 7 days old, receipts cannot be from later dates, and later movements remain reserved. For earlier dates, availability is limited by the minimum remaining batch balance from that day's end to now. Movements are effective at the end of the selected day, without inferring an actual sale time; reasons retain actual entry time. An insufficient-stock rejection rolls back the full sale transaction. Corrections reverse and reallocate against the original date, preserving audit records.

Production keeps its existing rules: quantity differences on correction, dated rates, saved cost snapshots, current recipe for newly entered past days, current material inventory deductions and actual submission audit time. Missing-production popups and push reminders still check today's production only.

Migration `migration_sale_entry_date.sql` adds nullable recording time without inventing timestamps for existing sales. Applied at startup. Regression tests: `test_dated_sales.py`, `test_production_entry_policy.py`, `test_customer_allocations.py`, `test_sales_tax.py`, `test_push_reminders.py`. Isolated database verification covers creation/listing/receipts, duplicate submissions, corrected quantities, effective ledger/movement dates, payment locks, changing allowances and transaction rollback. No production test invoices are required.
